# 复借G卡样本与取样口径

更新时间：2026-07-02

本文是复借 G 卡项目的样本口径说明，面向后续建模、评估和交接查阅。原始 SQL 留档见 `docs/复借G卡取样逻辑.sql`。本文只解释口径，不作为 `rmw` 工作流的执行配置。

## 1. 资料边界

| 项目 | 说明 |
|---|---|
| 原始留档 | `docs/复借G卡取样逻辑.sql` |
| 历史最终基准样本表 | `pdm_risk.pdm_risk_gcard_base_sample_uid_ds_eva_ben_v6_1` |
| 当前项目配置样本表 | `ads_app_off_feature.ds29531_backtrack_fj_gcard_model_v6_1_sample` |
| 主键口径 | `uid + mdl_dte` |
| 分区/观察日字段 | `ds` |
| 建模日期字段 | `mdl_dte = ds + 1` |
| 标签字段 | `ftr_30d_ord_flag` |
| 切分字段 | `final_flag` |

注意：历史 SQL 最终表与当前 `project.yml` 中登记的回溯样本表并不完全同名。后续如果要做严格复现，需要先确认两者之间的加工链路或同步关系。

## 2. 入样基础

基础人群来自 `pdm_risk_ftr.blue_customer_group_df` 的日更客群表。

入样客群：

| 客群取值 | 业务含义 |
|---|---|
| `E2` | 次新户 |
| `E3` | 老户 |
| `B2` | 流失户 |

样本观察日为 SQL 中硬编码的 48 个日期，覆盖 2025-06 至 2026-01。每个观察日都会生成下一日的建模日期 `mdl_dte`。

## 3. 可经营过滤

SQL 先基于 `pdm_risk.pdm_risk_hlm_cus_type_new_df` 生成经营状态标签 `cus_type_hlm`，再只保留：

```sql
cus_type_hlm = '可经营用户'
```

这意味着样本并非全量 E2/E3/B2 用户，而是先经过可经营状态过滤后的经营候选人群。

## 4. 当前逾期过滤

SQL 根据还款计划和订单信息计算：

| 字段 | 含义 |
|---|---|
| `max_cur_ovd_day` | 当前逾期最大天数 |
| `max_his_ovd_day` | 历史逾期最大天数 |

后续样本构造只保留：

```sql
max_cur_ovd_day <= 0
```

即当前未逾期用户。历史逾期字段可用于观察或切片，但不是当前入样排除条件。

## 5. 标签定义

标签来自观察日后的重资产发起行为：

```sql
ftr_30d_ord_flag = 1 when ftr_30d_ord_cnt > 0 else 0
```

其中 `ftr_30d_ord_cnt` 统计观察日后 1-30 天内的重资产发起次数。重资产业务类型包括：

| 业务类型 |
|---|
| `BUSINESS_LOAN` |
| `BALANCE_TRANSFER` |
| `CASH` |
| `HB_IMPREST` |
| `CREDIT_TRANSACTION` |
| `HUGE_LOAN` |

## 6. 训练样本抽样

在每个 `ds` 内，对当前未逾期样本按随机数排序：

```sql
row_number() over(partition by ds order by rand(2555)) as rn
```

每个观察日取：

```sql
rn <= 100000
```

被抽中的样本标记为 `sample_flag = 'train'`，未抽中的样本标记为 `sample_flag = 'untrain'`。

## 7. OOS 样本定义

未进入训练抽样的用户中，如果该 `uid` 从未出现在训练样本里，则标记为：

```sql
all_sample_tag = 'OOS-untrain'
```

如果该 `uid` 已经在训练样本中出现，则仍按 `INS` 处理，不进入 OOS 独立样本。

这套逻辑的目标是让 OOS 更接近“训练样本外的新 uid”，而不是同一批 uid 的未抽中观测日。

## 8. 时间切分

时间切分基于 `mdl_dte`：

| 条件 | `time_window` |
|---|---|
| `mdl_dte < '2025-12-01'` | `DEV` |
| `mdl_dte >= '2025-12-01'` | `OOT` |

最终 `final_flag` 由训练抽样、OOS 标识和时间窗口共同决定：

| 条件 | `final_flag` |
|---|---|
| `sample_flag = 'train'` 且 `time_window = 'DEV'` | `DEV` |
| `sample_flag = 'train'` 且 `time_window = 'OOT'` | `OOT` |
| `all_sample_tag = 'OOS-untrain'` 且 `time_window = 'DEV'` | `DEV-OOS` |
| `all_sample_tag = 'OOS-untrain'` 且 `time_window = 'OOT'` | `OOT-OOS` |

## 9. OOS 二次抽样

由于未参与训练的日更样本量较大，SQL 对 `DEV-OOS` 和 `OOT-OOS` 又按 `ds` 做一次随机抽样：

```sql
row_number() over(partition by ds order by rand(255)) as rn
```

每个观察日保留：

```sql
rn <= 100000
```

因此，OOS 样本不是全量未训练样本，而是按日抽样后的评估样本。

## 10. 历史基准分拼接

最终 benchmark 表拼接了历史 G 卡模型分：

| 字段 | 来源说明 |
|---|---|
| `gcard_v2` | 历史 G 卡 V2 对齐表 |
| `gcard_v4` | 历史 G 卡 V4 分表 |
| `gcard_v5` | 长流失意愿模型分 |
| `gcard_v6` | G 卡 V6 模型分 |

这些字段用于 champion/challenger 对比，不应和候选特征混淆。

## 11. 泄漏边界

原始 SQL 里包含若干未来窗口字段，例如：

| 字段类型 | 示例 | 建议用途 |
|---|---|---|
| 标签字段 | `ftr_30d_ord_flag` | 目标变量 |
| 未来发起统计 | `ftr_7d_ord_cnt`、`ftr_30d_ord_amt` | 标签构造或分析，不作为训练特征 |
| 未来风险表现 | `prc_amt_xz_30d_3m`、`ovd_amt_xz_30d_3m` | 风险观察或报告解释，不作为训练特征 |
| 历史基准分 | `gcard_v2`、`gcard_v4`、`gcard_v5`、`gcard_v6` | 对标评估，不作为新模型候选特征 |

后续如果从该表取建模输入，应显式排除未来窗口字段和历史基准分，避免标签泄漏或评估污染。

## 12. 待确认问题

1. 当前 `project.yml` 的回溯样本表与历史最终基准样本表之间的生产关系。
2. 48 个硬编码观察日是否为正式业务口径，还是一次性抽样策略。
3. 每日 `100000` 的训练/OOS 抽样上限是否仍适用于后续版本。
4. OOS 的“新 uid”定义是否需要在后续模型验收中继续沿用。
5. `prc_amt_xz_30d_3m`、`ovd_amt_xz_30d_3m` 与历史 MOB 风险口径是否一致。

## 13. 维护原则

- 原始 SQL 保持留档，不直接改写为执行脚本。
- 若未来要复现或重跑样本，应新建版本并通过 `rmw` 的请求、计划和版本流程登记。
- 若发现本文与 SQL 不一致，以 SQL 留档为历史证据，以当前版本产物和 `artifact_manifest.json` 为执行证据。
